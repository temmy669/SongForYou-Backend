# Deploying songForyou to Render

The backend deploys from [`render.yaml`](render.yaml) as a Render Blueprint: a
single web service. The database is **Neon**, provisioned separately, so Render
creates no Postgres instance — there is no `databases:` block in the blueprint.

---

## 1. Commit the repo

Nothing is committed yet. From the project root:

```bash
git add .
git commit -m "Backend ready for deploy"
git remote add origin <your-repo-url>
git push -u origin main
```

`.env`, `db.sqlite3`, `venv/` and `staticfiles/` are gitignored and must stay
that way. `.env` holds your Spotify secret — if it ever gets committed, rotate
the secret in the Spotify dashboard rather than just deleting the file, because
it stays in git history.

## 2. Create the Blueprint

Render Dashboard → **New** → **Blueprint** → pick the repo. Render reads
`render.yaml` and prompts for the values it will not store in git:

| Variable | Value |
|---|---|
| `SPOTIFY_CLIENT_ID` | From the Spotify dashboard |
| `SPOTIFY_CLIENT_SECRET` | From the Spotify dashboard |
| `FRONTEND_URL` | Where the frontend is hosted, e.g. `https://songforyou.vercel.app` |
| `CORS_ALLOWED_ORIGINS` | Same origin as above, scheme included |
| `ALLOWED_HOSTS` | Leave blank for now |
| `CSRF_TRUSTED_ORIGINS` | Leave blank for now |
| `DATABASE_URL` | Your Neon connection string — see below |

`SECRET_KEY` is generated by Render; you never set it by hand.

### The Neon connection string

Copy it from the Neon console. Use the **pooled** endpoint — the host containing
`-pooler` — and keep the `sslmode=require` parameter:

```
postgresql://<user>:<password>@ep-xxxx-pooler.<region>.aws.neon.tech/<db>?sslmode=require
```

This is a secret. It is set in the Render dashboard, never committed.

Three things are configured for Neon in `settings.py`, and all three matter:

- **`conn_health_checks=True`** — Neon suspends idle compute (~5 min on free
  plans) and drops its connections. Connections are pooled for 10 minutes, so
  without this Django hands out a dead one after a quiet period. The symptom is
  distinctive: the first request 500s with *"server closed the connection
  unexpectedly"* and an immediate retry succeeds.
- **`ssl_require=True`** — Neon refuses non-TLS connections. This fails closed
  if the URL is ever pasted without `sslmode=require`.
- **`disable_server_side_cursors`** — Neon's pooled endpoint is PgBouncer in
  transaction mode, which cannot hold a cursor open across statements. If you
  ever switch to a direct (non-pooler) endpoint, set `DB_SERVER_SIDE_CURSORS=True`
  to get them back.

Leaving the two host variables blank is safe: `settings.py` trusts
`RENDER_EXTERNAL_HOSTNAME`, which Render injects, so the service accepts requests
on its own `.onrender.com` URL from the first deploy. Fill them in when you
attach a custom domain.

## 3. Point Spotify at the deployed backend

In the [Spotify dashboard](https://developer.spotify.com/dashboard), add the
production redirect URI **alongside** the local one — replacing it breaks local
development:

```
http://localhost:8000/accounts/spotify/login/callback/
https://<your-service>.onrender.com/accounts/spotify/login/callback/
```

The path must match exactly, trailing slash included.

## 4. Create the admin user

Migrations ran against Neon during the build. Once the first deploy is green,
open the service's **Shell** tab:

```bash
python manage.py createsuperuser
```

You do not need to run migrations here.

## 5. Verify

```bash
curl https://<your-service>.onrender.com/health/
# {"status": "ok"}
```

Then check, in order:

1. `/admin/` loads **with styling**. Unstyled means `collectstatic` did not run.
2. `/accounts/spotify/login/` completes and lands back on `FRONTEND_URL` with a
   `?token=` parameter.
3. The frontend can call `/api/search/?q=test` without a CORS error.

## What the build does

`build.sh` runs on every deploy:

```bash
pip install -r requirements.txt
python manage.py collectstatic --no-input
python manage.py migrate --no-input
```

`collectstatic` is **not optional**. `staticfiles/` is gitignored, so the repo
Render clones contains no static assets, and production uses
`CompressedManifestStaticFilesStorage`, which raises on a missing manifest
instead of degrading. Without this step every `/admin/` and DRF browsable-API
page returns 500.

Migrations run in the build because Render's free plan has no pre-deploy hook.
If you move to a paid plan, prefer a `preDeployCommand` so a failed migration
stops the release before it goes live.

Neon is reachable from Render's build environment, so the migration step works
there. If Neon's compute is suspended when a build starts, the first connection
wakes it — expect a few seconds of delay, not a failure.

## After the first deploy: turn on HSTS

`SECURE_HSTS_SECONDS` ships at `0` deliberately. HSTS is **cached by browsers and
cannot be undone by redeploying** — a wrong value is a self-inflicted outage that
you cannot fix from your side.

Ramp it:

1. Confirm HTTPS works on every hostname you serve.
2. Set `SECURE_HSTS_SECONDS=3600`, redeploy, wait a day.
3. Raise to `31536000` (one year).
4. Only then consider `SECURE_HSTS_INCLUDE_SUBDOMAINS` / `SECURE_HSTS_PRELOAD`.

## Known constraints

- **Free tier sleeps.** The service spins down after inactivity, so the first
  request after a quiet period takes ~30s. That is long enough to look broken at
  a venue — move to a paid instance before a real event.
- **Neon free tier auto-suspends.** Idle compute scales to zero, so the first
  query after a quiet period pays a cold-start. Combined with Render's own
  spin-down, a venue's first request can be slow twice over.
- **Neon storage is not backed up by Render.** Snapshots and point-in-time
  restore are configured in the Neon console, separately.
- **No rate limiting** on any endpoint, including public track search.
- **Local Python is 3.10, deployed is 3.12** (`.python-version`). Nothing in the
  dependency set is affected, but align them if you hit anything odd.

## Local development

```bash
cp .env.example .env
# fill in SECRET_KEY, SPOTIFY_CLIENT_ID, SPOTIFY_CLIENT_SECRET
python manage.py migrate
python manage.py runserver
```

`DEBUG=True` relaxes hosts and CORS for local work. Run the tests with:

```bash
python manage.py test requester
```
